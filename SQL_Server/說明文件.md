# SQL Server 閒置 Lock Session 自動解除

## 1. 檔案說明

| 檔案 | 用途 |
|---|---|
| [KillIdleBlockingSession.sql](./KillIdleBlockingSession.sql) | **執行 SQL**：建立紀錄表、Procedure、SQL Agent Job（每 20 分鐘） |
| [Test-KillIdleBlockingSession.ps1](./Test-KillIdleBlockingSession.ps1) | 自動化驗證腳本（部署 + 情境測試） |
| [k8s-sqlserver-test.yaml](./k8s-sqlserver-test.yaml) | 在 k8s 部署 SQL Server 2019/2022 測試環境 |

## 2. 運作邏輯

SQL Agent Job `DBA - Kill Idle Blocking Sessions` 每 20 分鐘執行
`master.dbo.usp_KillIdleBlockingSession`，同時符合下列條件的 Session 會被 `KILL`：

1. 使用者連線（`is_user_process = 1`），且不是執行者自己
2. `status = 'sleeping'`，且沒有任何執行中的 request（即範本的 `AWAITING COMMAND`）
3. `last_request_end_time` 距今超過 30 分鐘
4. 目前**正在阻塞**其他 Session（有其他 request 的 `blocking_session_id` 指向它）
5. 所在資料庫在 `@DatabaseList` 內（預設 `ctrlmdb`、`emdb`）

KILL 前會再確認一次（仍閒置、`last_request_end_time` 未變、仍在阻塞他人），避免誤殺剛恢復活動的連線。
每次動作寫入 `master.dbo.IdleSessionKillLog`（KILLED / WHATIF / FAILED，保留 90 天）。

與範本 `session_Lock解除範本.txt` 的差異：

- 改用 `sys.dm_exec_sessions` / `sys.dm_exec_requests`（SQL Server 2012 以上皆有；`sys.sysprocesses` 為相容性檢視，不建議使用）。
- 範本固定 `ctrlmdb, emdb`，改為參數 `@DatabaseList`（預設與 Job 皆為 `N'ctrlmdb,emdb'`，設為 `NULL` 則處理所有資料庫）。
- 加入紀錄、WhatIf、KILL 前複查與錯誤處理。

## 3. 部署

以 sysadmin 身分在 SSMS / sqlcmd 執行整份 [KillIdleBlockingSession.sql](./KillIdleBlockingSession.sql)（可重複執行，會覆蓋舊版 Procedure 與 Job）：

```
sqlcmd -S <server> -U <user> -P <password> -C -i KillIdleBlockingSession.sql
```

> 檔案為 UTF-8 with BOM，請勿移除 BOM，否則 sqlcmd 會將中文註解/Job 說明當成亂碼。

### 參數

| 參數 | 預設 | 說明 |
|---|---|---|
| `@IdleMinutes` | 30 | 閒置門檻（分鐘） |
| `@DatabaseList` | `N'ctrlmdb,emdb'` | 逗號分隔；NULL 為全部資料庫 |
| `@WhatIf` | 0 | 1 = 只列出與記錄，不實際 KILL |
| `@LogRetainDays` | 90 | 紀錄保留天數 |

已指定只處理 `ctrlmdb`、`emdb`（Job Step 已設定）。如需調整，修改 Job Step：

```sql
EXEC dbo.usp_KillIdleBlockingSession @IdleMinutes = 30, @DatabaseList = N'ctrlmdb,emdb';
```

上線前建議先 `@WhatIf = 1` 觀察 `IdleSessionKillLog`。

## 4. 維運

```sql
-- 查詢紀錄
SELECT TOP 100 * FROM master.dbo.IdleSessionKillLog ORDER BY LogId DESC;
-- 立即手動執行 Job
EXEC msdb.dbo.sp_start_job N'DBA - Kill Idle Blocking Sessions';
-- 暫停 / 啟用
EXEC msdb.dbo.sp_update_job @job_name = N'DBA - Kill Idle Blocking Sessions', @enabled = 0;
```

## 5. 注意事項

- 需要 SQL Server Agent；Express 版本無 Agent，請改以 Windows 工作排程器或 k8s CronJob 每 20 分鐘執行 `EXEC master.dbo.usp_KillIdleBlockingSession;`。
- Job 擁有者需有 `ALTER ANY CONNECTION` 與 `VIEW SERVER STATE`（sysadmin 即可）。
- KILL 會回滾該 Session 的未提交交易，若交易很大，回滾期間資源仍被佔用；應用程式需有重連機制。
- AlwaysOn AG 環境請在各副本部署；`database_id` 為 Session 當前資料庫，若連線在 A 資料庫但鎖住 B 資料庫的資源，`@DatabaseList` 以 A 為準。
- 時間以伺服器 `GETDATE()`（本地時間）計算。

## 6. 測試

測試腳本會：部署（連跑兩次確認可重複）→ 檢查 Job 排程 → 建立 4 條連線（閒置阻塞者 A、被阻塞者 B、閒置持鎖但未阻塞者 C、閒置無交易者 D）→ 驗證：

| 情境 | 預期 |
|---|---|
| 閒置未滿 30 分鐘 | 不 KILL |
| `@WhatIf = 1` | 不 KILL，寫入 WHATIF 紀錄 |
| 資料庫不在 `@DatabaseList` | 不 KILL |
| 條件全符合 | 只 KILL A，B 隨即完成，C、D 不受影響，寫入 KILLED 紀錄 |
| 手動執行 Agent Job | 成功 |
